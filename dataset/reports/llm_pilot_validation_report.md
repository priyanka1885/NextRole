# LLM Semantic Annotation -- Pilot Validation Report

Model: `llama3.1:8b` (local Ollama). Pilot size: **100** records, stratified by original source label with seed=42. Generated by `dataset/scripts/07_llm_semantic_pilot.py`.

## 1. Status: PILOT ONLY -- gate not yet cleared

This report covers a 100-record sample only. **The full 6,240-record dataset has NOT been processed** and no script in this pipeline will do so automatically. Promoting this method to the full dataset (or to `golden_eval_dataset.csv`) is a separate, deliberate decision that should only be made after a human reviews:

- The agreement/disagreement counts and confusion matrix below.
- A sample of `dataset/output/llm_pilot_annotated.csv` decision_reason text for reasoning quality.
- The **22** record(s) flagged by the fabrication guardrail (claimed matching_skills with no literal trace in the resume).
- The **0** record(s) where the LLM call failed after retries (`annotation_status == "llm_pilot_failed"`).

## 2. Run Summary

- Label distribution sampled: {'No Fit': 50, 'Potential Fit': 25, 'Good Fit': 25}
- LLM calls: 100 succeeded, 0 failed
- Mean latency per call: 93.94s (total: 9394.4s)
- `annotation_status` counts: {'llm_pilot_annotated': 100}

## 3. Agreement with Original Source Label

The LLM's independently-derived `decision` compared against the untouched original 3-class `label` (which remains `expected_decision` throughout -- never overwritten):

- **Agreement rate: 47.0%** (47 agree / 53 disagree, of 100 successful calls)
- Confusion matrix (`original_label -> llm_decision`: count):
  - `Good Fit -> Good Fit`: 1
  - `Good Fit -> No Fit`: 9
  - `Good Fit -> Potential Fit`: 15
  - `No Fit -> Good Fit`: 1
  - `No Fit -> No Fit`: 33
  - `No Fit -> Potential Fit`: 16
  - `Potential Fit -> Good Fit`: 7
  - `Potential Fit -> No Fit`: 5
  - `Potential Fit -> Potential Fit`: 13

Disagreement is not automatically treated as an LLM error -- this pipeline's own earlier audits found genuinely wrong source labels (see `dataset/reports/annotation_guidelines.md` §4/§6). A human reviewer should read the disagreeing records' `decision_reason` and resume/JD text directly before concluding which side (source label or LLM) is correct for each one.

## 4. Guardrails Applied

- `expected_decision` is the original source label for all 100 records -- verified never overwritten by the LLM's `decision`.
- Every `matching_skill` the LLM claims is checked for at least a loose word-level textual trace in the resume; unsubstantiated claims are flagged inline in `decision_reason`, not silently trusted.
- Failed LLM calls (malformed JSON/schema after the client's built-in retries) are recorded as `annotation_status == "llm_pilot_failed"`, never silently guessed or dropped.
- `annotation_status`/`annotation_source` clearly mark every record as machine-generated (`llm_pilot_annotated` / `llm_pilot_failed`); no record is ever marked `human_verified`.
